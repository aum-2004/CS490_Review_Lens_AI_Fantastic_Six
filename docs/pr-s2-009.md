# S2-009: Add the Review Q&A interface and production integration

Refs #60. Integrates the existing S2-010/S2-011/S2-013 services for #61, #62 and #64;
does not close their remaining integration acceptance work.

Users can ask a natural-language question from the active AnalysisTarget workspace
and see processing, a ReviewLens answer, insufficient evidence, a scope refusal or
a useful failure message. The target and Google Maps platform remain visible.
Failed questions are retained for retry; changing targets clears the form and
aborts pending UI requests so late replies cannot populate the new workspace.

The production questions route calls `answerQuestion()` with the real
`buildReviewDatasetContext(targetId)` and model adapter. It authenticates, checks
ownership before input/context reads, bounds JSON/question sizes, ignores browser
ownership/evidence claims and returns validated target-tagged, private/no-store
responses. Context failures make no provider call. Server field errors share the
accessible client error display; logs contain safe categories rather than inputs
or provider diagnostics.

## Configuration and review

Q&A remains disabled unless `QA_ENABLED=true`, with server-only `OPENAI_API_KEY`
and an explicit supported `OPENAI_QA_MODEL`. Dataset limits are 100 reviews and
32,768 evidence bytes; the adapter checks the provider's full input count plus
1,500 reserved output tokens against a 16,000-token cap. Requests above 128 KiB
are rejected before even the counting request is sent. Context failures make
neither counting nor generation requests.
