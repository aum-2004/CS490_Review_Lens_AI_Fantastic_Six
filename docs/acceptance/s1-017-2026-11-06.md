## Additional observed behavior

- All three User A records remained after refresh and home navigation despite the provider's two-row response cap.
- API responses contained only `id`, `name`, `platform`, `sourceUrl` and `createdAt`, with private/no-store directives.
- The empty account saw an explicit empty state and the S1-015 creation link.
- The failing account saw generic retry feedback, not a successful empty/partial list. Retry remained safe; the API returned 500 with no data or provider diagnostic.
- Desktop (1280px) and mobile (375px) screenshots were inspected in light mode; mobile was also inspected in dark mode. Cards and source links were readable, navigation remained usable, and mobile had no horizontal overflow. This is visual inspection, not a full WCAG audit.
- The first Tab focused the skip link; Enter focused main. The account menu opened with Enter and closed with Escape, restoring trigger focus.
- After logout, User A's API request returned 401 and protected navigation returned 303. Browser Back settled on `/login?next=%2Fanalysis-targets`, with the sign-in form visible and no visible target card. User B's independent session still returned 200.
- No unhandled browser runtime errors were recorded.
- Open and New Target links have the agreed S1-018/S1-015 destinations. Those owning screens are not acceptance-tested as implementations of this story.
