# PR title

S2-017: Switch between owned analysis targets with clear active context

## PR description

Closes #68.

Adds a **Switch target** control to the workspace header. Users can navigate directly to another
owned target, see which target is active, and distinguish duplicate target names by their saved
source URLs. The active identity remains clear in the workspace, ingestion card, and Q&A.
Switching uses the existing target URLs, preserving refresh and browser history behavior.

The switcher supports keyboard navigation and Escape dismissal with focus restoration. Empty
and failed switch lists explain the next step without discarding the current workspace.

### Security and context isolation

- Authenticate and verify target ownership before loading the switch list or child data.
- Reuse the owner-filtered list and session-scoped Supabase client; send only ID, name, and
  source URL to the switcher. Missing and foreign targets remain indistinguishable.
- Render names and sources as escaped text; switch links use fixed internal routes and encoded
  target IDs.
- Preserve existing target-scoped Q&A context rebuilding, form reset, pending-request
  cancellation, response-target validation, and empty-dataset restrictions.

No schema, RLS, grants, dependency versions, or provider integrations changed. The existing
200-target list limit remains.
