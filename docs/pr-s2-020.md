# S2-020: Handle targets without review data

Closes #71.

Targets without saved reviews now show an accessible explanation beside disabled
question controls. The workspace distinguishes empty datasets, failed or ongoing
ingestion, review-load failures, and completed ingestion with missing saved rows.
Previously saved reviews remain usable after a later ingestion failure.

Retains the backend's authenticated, target-owned review-context guard: empty
datasets return HTTP 409 `NO_REVIEW_DATA` before quota reservation, token counting,
or model generation. Regression tests verify that general-knowledge instructions,
forged browser evidence, and prior-target context cannot bypass this guard, and
that unavailable datasets clear stale answers and cancel pending UI requests.

Validation:

- 82 Jest suites / 1,514 tests passed; changed-line coverage 100% (29/29).
- Five browser tests passed against the production build, including desktop/mobile
  empty states, reload, and direct empty-target API rejection.
- Lint, typecheck, formatting, production build, and `git diff --check` passed.

The functionality/security review corrected a misleading recovery instruction for
completed ingestion with no saved rows; no blocking findings remain in the reviewed
scope. Tests use synthetic fixtures with isolated model calls. Live provider and
deployed database configuration were not audited. No migrations or dependencies
changed. Local browser-runner teardown required stopping its own fixture/server
processes after all cases passed.
