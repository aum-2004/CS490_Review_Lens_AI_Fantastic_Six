# S2-020: Handle targets without review data

Refs #71.

Targets without saved reviews now show an accessible explanation beside disabled
question controls. The workspace distinguishes empty datasets, failed or ongoing
ingestion, review-load failures, and completed ingestion with missing saved rows.
When collection is disabled, storage is not approved, or recovery is not configured,
Q&A shows the same unavailable reason as the ingestion panel instead of directing
users to a disabled action. Previously saved reviews remain usable after ingestion
failures or configuration blockers.

Retains the backend's authenticated, target-owned review-context guard: empty
datasets return HTTP 409 `NO_REVIEW_DATA` before quota reservation, token counting,
or model generation. Regression tests verify that general-knowledge instructions,
forged browser evidence, and prior-target context cannot bypass this guard, and
that unavailable datasets clear stale answers and cancel pending UI requests.

Validation:

- 89 Jest suites / 1,596 tests passed; changed-line coverage against `origin/main`
  100%.
- Added 12 configuration/state cases for unavailable ingestion and three cases
  verifying that configuration blockers still allow Q&A over saved reviews.
- All 36 authenticated browser tests passed against the production build, including
  desktop/mobile empty states, direct empty-target API rejection, keyboard target
  switching, summary context, history/refresh, delayed replies, and account changes.
- Lint, typecheck, formatting, production build, and `git diff --check` passed.

Tests use synthetic fixtures with isolated model calls; live provider behavior and
deployed database configuration were not audited. The local browser fixture includes
the single summary RPC retained by merged S2-017/S2-018. Local browser-runner teardown required stopping its own fixture/server
processes after all cases passed. No migrations or dependencies changed in this PR.
