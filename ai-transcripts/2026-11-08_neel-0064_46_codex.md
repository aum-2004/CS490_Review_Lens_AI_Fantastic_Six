## Review notes

Accepted:

- Add one forward-only migration that introduces validated database size backstops without changing
  or truncating existing review data.
- Inspect existing rows after adding the constraints as `NOT VALID`; abort with per-field violation
  counts and a manual-remediation hint before validating the constraints.
- Remove all direct `INSERT` privileges on `public.reviews` from browser-facing roles, including
  the old authenticated column grants, while retaining authenticated `SELECT`.
- Add an authenticated-only `SECURITY DEFINER` RPC with a fixed empty `search_path`, explicit
  ownership checks through `auth.uid()`, a strict field allowlist, field and request limits, and a
  single atomic insert statement.
- Keep target identifiers as text at the RPC boundary so malformed, missing, and foreign target
  identifiers can all return the same `Target unavailable` result.
- Continue using the existing user-scoped Supabase server client and route behavior; change only the
  review store's persistence operation from direct table insertion to the RPC.
- Preserve the service-role-only `finish_ingestion_attempt` workflow and verify it through the full
  clean-database suite.
- Add PostgreSQL coverage for direct table/Data API denial, function permissions, ownership,
  malformed inputs, atomicity, exact and over-limit values, Unicode, metadata bytes, and app-limit
  compatibility.
- State explicitly that an owner can still submit fabricated reviews through the protected RPC;
  this change does not establish provider-authenticated provenance.

Changed during validation:

- The existing route test's in-memory Supabase client initially modeled only table inserts, so the
  focused route suite returned HTTP 500 after the store moved to `rpc(...)`. The fake was updated to
  model the new user-scoped RPC contract; the focused suites then passed all 80 tests.
- `npm run test:db` could not start directly on Windows because `bash` was not on `PATH`; Git Bash
  was present but PostgreSQL client tools were not. Docker Desktop was started and an isolated
  PostgreSQL 16 container was used instead.
- The repository's Windows checkout gave shell files CRLF endings inside the Linux container. Only
  temporary container copies of the database runner scripts were normalized; repository files were
  not rewritten. The full database suite then passed.
- The migration revokes direct `INSERT` from `PUBLIC` and `anon` as well as `authenticated`, making
  the anonymous denial explicit and resilient to permission drift.

Rejected or deferred:

- Modifying an existing migration was rejected; the fix is forward-only.
- A service-role client for the review API was rejected because the endpoint must retain the user's
  authenticated identity and the RPC must authorize with `auth.uid()`.
- Accepting a client-supplied owner identifier was rejected; the RPC derives ownership exclusively
  from the authenticated session and target row.
- Silent deletion or truncation of pre-existing over-limit data was rejected. Hosted violations,
  if any, require operator review before the migration can be retried.
- Claims of provider-authenticated review provenance were rejected. The RPC closes direct table
  writes but still permits target owners to submit validation-compliant review content.
- Hosted Supabase changes, paid provider ingestion, automatic PR merging, and unrelated Issue #46
  follow-ups were outside scope.
